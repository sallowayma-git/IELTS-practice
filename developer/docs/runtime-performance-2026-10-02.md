# 运行速度优化（2026-10-02）

分支：`codex/runtime-performance`。JavaScript 基线：`46e3798d`。已有未提交的 `performance-data-audit-2026-09-30.md` 未被本轮修改。

## 已实现策略

1. **并行下载，按依赖顺序执行**：`ensureGroup` 在 HTTP/HTTPS 下提前为整个依赖图创建 script preload，消除练习包下载完成后才开始下载题库包的串行等待；标准化带版本 URL，并合并同资源并发加载。失败保留重试，file 协议与不支持 preload 的浏览器继续按原顺序注入。
2. **交互意图预取**：导航悬停、键盘聚焦只下载资源，不执行视图初始化；点击后才执行。开启浏览器 save-data 时跳过意图预取。显式 `AppActions` 模块就绪接口仍保留原行为。
3. **拆出虚拟滚动运行时**：原 `VirtualScroller` 仅存在于按需诊断包，普通练习页因缺少组件而一次渲染全部历史。现在独立组件包含在题库运行包中；诊断包复用同一构造器。5,000 条记录仅渲染约 30 个首屏节点。修复网格滚动定位、筛选缩减后的滚动位置和销毁时残留回调；选择状态来自完整记录集合。
4. **批量布局测量**：历史列表先插入全部样本，再读取几何尺寸，避免最多 30 次交替写 DOM / 强制布局；异常也会清理测量节点。
5. **减少重复计算**：分类进度从每条记录重复查找题目，改为一次 Map 索引和 Set 聚合；概览显示内容相同时保留 DOM。详情弹窗一次渲染内共享答案归一化结果，结束后释放，后续打开读取当前内容；套题汇总改为线性追加。
6. **背景按需渲染**：默认静态 floral-bloom 背景由持续 24 fps 重绘改为初始化、尺寸变化或显式刷新时渲染；动态背景在隐藏或减少动态效果时取消循环，恢复后只启动一个循环。

所有发布 bundle 和诊断构建产物已重新生成。

练习再次打开在上述两种规模下降约 43% / 36%。题库首次打开没有提速，不把并行下载效果推广成所有页面都更快。全量导出、快照校验仍是主线程和大数据读取瓶颈。

HTTP 延迟独立实验：每个脚本延迟 180 ms。原串行加载 372 ms；新冷加载 186 ms，两次请求几乎同时发起；提前意图预取完成后模块执行约 1 ms（不包含此前 180 ms 下载）。实际网络请求均为 2 次，预取不执行脚本，随后执行顺序仍为 first → second。

打包应用断言：1,000 / 5,000 条历史首屏均为 30 个节点，底部约 20 个节点，最早记录仍可达。独立组件桌面双列与移动单列测试覆盖最后一条、勾选状态、过滤与销毁。

精读 1,000 词回归通过：书架初始 20 张卡、200 个预览词；翻页不读取完整词库；未查词前不加载字典；首次并发查词只请求一次字典。页面无 JavaScript 异常，发布环境无未打包 JS 依赖。仓库已有可选听力 manifest 缺失仍产生 404，沿用原降级行为。

## 切页掉帧优化

在同一分支继续优化，帧间隔基线是本报告前一轮优化完成后的工作区快照（`/tmp/ielts-navigation-before`），不是旧 Git HEAD。

- 页面外壳和导航状态立即更新；数据加载与视图激活移到下一帧后的任务。新导航取消旧任务；题库重置屏障、筛选意图和请求归属保留。连续点击练习页时，待激活标记持续到异步模块和记录同步结束，避免旧任务被取消后遗漏新激活。
- 隐藏练习页只保留最新摘要快照；再次激活时，即使内容签名未变也恢复渲染。准确率、趋势和卡片计算分成独立任务，检查最新快照与导航归属；不继续渲染已经离开的页面。
- 历史日期排序每条只解析一次；按题目匹配使用索引；最近 10/20 次趋势不用排序全部历史。
- IndexedDB 摘要读取完成事务后，按最多 100 行或约 6 ms 的预算校验、复制，再让出主线程。仍验证每条校验和、过滤损坏行并保持顺序；只在全部处理结束后返回。IDB `getAll` 结果已经脱离存储，取消多余的整表复制；写事务与备份校验语义保持不变。
- Emoji 转换改为每批最多 150 个节点、约 4 ms 的空闲工作，合并重复根节点，跳过代码、编辑器、SVG 和自身图标。显式 `refresh()` 仍同步执行。
- 导航滑块只对 `transform` / `opacity` 做过渡，尺寸直接更新；移除强制重排，并修复观察器由自身 readiness class 更新造成的重复调度。

### 帧间隔测量

隔离 Chromium，5,000 条记录，CDP 将 CPU 降速 4 倍；每次实际导航点击后采样约 1 秒。记录的是 `requestAnimationFrame` 回调间隔和主线程 Long Task，不是硬件实际显示 FPS。热切换重复两次，表中保留两次范围；本机测量不代表统计意义上的跨设备改善。

| 场景 | 前一轮最大帧回调间隔（ms） | 本轮最大帧回调间隔（ms） |
| --- | ---: | ---: |
| 首次题库 | 138 | 69 |
| 首次练习 | 406 | 194 |
| 首次概览 | 397 | 109 |
| 再次练习 | 395–396 | 110–122 |
| 再次概览 | 386–387 | 211–236 |
| 再次题库 | 268–273 | 245–268 |
| 再次设置 | 40–41 | 43–52 |
| 再次更多 | 38–39 | 37–38 |

再次练习的窗口内长任务总时长从 954–1011 ms 降到 177–182 ms。首次更多仍有约 397 ms 最大帧间隔；题库热切换与概览仍存在超过一帧的阻塞，尚不能承诺全程 60 FPS。后续应优先拆分题库进度索引和概览统计，或者在可保留快照归属检查的前提下移至 Worker。

全套测试通过 686 项；随后增加异步加载中重复点击与题库请求计数器初始化的回归，与相关 39 项测试再次通过。18 个 bundle 一致性、5,000 条记录打包导航和独立键盘导航/减少动画/编辑内容保护检查通过。切页测量还检查连续四次导航的最终页面、记录总量和页面异常。完整书架端到端回归的 18 个案例在 HTTP / HTTPS / file 三种协议均通过。冷启动时请求计数器从不可用变为初始 0 被识别为初始化；真正的新前台请求仍取消旧刷新。
