# 九分学长插件第一阶段取样清单

本机已经取得这篇阅读的取题与复盘样例，并根据同一次作答重建交卷核心字段。剩余联调材料及样例来源见 [本机取样结果](samples/humans-and-food/README.md)。

交付单位为同一测试环境、同一测试账号、一套可授权用于联调的阅读练习和一次对应的作答。一个 JSON 文件可容纳多次调用。每次调用保留 HTTP 方法、路径模板、状态码、业务码、请求体和响应体。注明环境名称和 API 版本，方便区分原客户端环境与 Atlas 联调环境。

## 五组配对样例

| 建议文件名 | 服务端导出内容 | 用来验证 |
|---|---|---|
| `01-email-login.json` | 发送邮箱验证码、验证码登录各一次成功请求与响应。保留字段名、值类型、会话传递位置、有效期及稳定账号标识。若接口另行获取账号信息，附对应响应。已有的错误码文档可用于补充过期、冷却和撤销规则。 | 设置页能发码、识别登录成功、绑定正确账号，过期后恢复本机草稿。 |
| `02-access-and-catalog.json` | 测试账号的阅读权限、实际取题模式、同一篇或套题对应的目录条目及父级 ID。如要求本地资源包，附获准 Part 的版本、内容指纹及测试端正式交付方式。 | 确定 Atlas 应调用的取题接口，区分目录可见与可开题。 |
| `03-reading.json` | 一套可完整提交的阅读单元，保留文章分段、题目说明、组与题的顺序、稳定题 ID、显示题号、选项的提交值、填空定位及字数限制。保留真实数据形态，例如空值、HTML 占位符和嵌套数组。可以用授权短文替换原文，保留做题所需的结构。 | 把同一份远端内容转换为本地可显示的题面，并建立双向题号与答案键映射。 |
| `04-submit.json` | 同一次作答的请求和回执，含选项答案、文本答案与留空题的真实编码、计时字段（如有）、本次提交标识和服务端作答 ID。最好能覆盖一题正确、一题错误和一题留空。附现有的重复提交或回执丢失后的查询约定。 | 本地先保存草稿，提交后关联官方结果。连接中断时能判断是否已交卷。 |
| `05-review.json` | 上一组作答 ID 对应的官方复盘响应。如列表与详情分开，同附列表中的那一行。保留逐题作答、对错或未答状态、官方给出的标准答案与解析、总分及计分单位。若分数需另一次调用才就绪，附最终响应。 | 关闭并重启 Atlas 后可按本地记录复盘。逐题结果和汇总分可与原客户端核对。 |

对可选字段保留“缺失”“空字符串”“null”“空数组”的原始区别。邮箱可用 `tester@example.invalid`。账号、套题、Part、题组、题、选项、作答的标识使用跨文件一致的别名，数字字段继续用数字。将验证码、Cookie、令牌、签名值及媒体地址中的授权参数替换为占位符。认证规则采用服务端维护的接口说明或官方 SDK 文档。

## 客户端核验基准

2026-11-18，在用户给出的安装目录打开原客户端，在“Z家阅读11月高频”进入 Part 1 的《A Brief History of Humans and Food》。考前页面显示第 1–5 题为 TRUE / FALSE / NOT GIVEN，第 6–13 题为笔记填空，每空限一个词。现场核验到计时选择页。该环境的 `resources/app.asar` 与先前检查的安装包内同名文件 SHA-256 相同。测试环境可选用自己的题目，只要有完整题面、同次提交和复盘即可。若目标是三篇整套考试，需提供三篇共用一次提交的样例，以核对换篇后的编号、计时和总分。

## 插件和本机数据的边界

- 九分学长的接口和字段转换集中在 `plug/jiufen/`。Atlas 设置页提供账号入口，宿主通过明确的 Tauri 命令调用插件。在用户的本机完成题面转换与作答恢复。
- 转换器给每道题保留上游 ID、显示题号和本地答案键。提交时反向转换成本次试题使用的上游标识和答案格式。原客户端的目录标题用于人读，跨系统关联使用稳定 ID。
- 本机 SQLite 保存题面版本或可复盘的快照、所属账号、草稿、提交状态以及服务器确认的逐题结果。远端会话凭据由宿主系统凭据库保存。官方回执与本地草稿使用同一个本地作答 ID 关联。
- 首轮验收包括重启后草稿可继续、填写值与提交值一致、重试只出现一条记录、断网可看已保存的复盘，以及切换账号后记录归属正确。
